# Contributing to Twoody

Thanks for helping improve Twoody. This repository is part of the Twoody Local open-source preview, so expect some APIs and workflows to move while the public contract settles.

## Ground Rules

- Keep changes focused: one pull request should solve one problem.
- Prefer small, reviewable commits with a message that explains why the change exists.
- Do not include secrets, customer data, device logs with tokens, or private backend URLs.
- New user-facing strings should be documented and, where relevant, routed through the host application's localization layer.
- For behavior changes, include tests or a clear manual verification note.

## Development Flow

1. Open an issue or discussion for larger changes before starting implementation.
2. Create a feature branch from `main`.
3. Run the repository's checks before opening a pull request.
4. Describe what changed, why, and how you verified it.

## Contributor License Agreement

Twoody will use a CLA before accepting external contributions to public repositories. Until the CLA bot is configured, maintainers may ask contributors to confirm authorship and license intent manually.

## Security

Please do not report vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).
